# Linux Systems Administration

## Learning Objectives
- Understand **Linux architecture** (kernel vs user space).
- Navigate the **shell environment** and write safe shell scripts.
- Manage the **file hierarchy**, users, groups, and **permissions** (numeric & symbolic).
- Manage **processes** and services (systemd).
- Administer **SSH** and remote access.

---

## Linux Architecture

Linux is a monolithic **Unix-like** OS: a **kernel** (privileged, ring 0) plus a **user space**
of shells, libraries, daemons, and apps.

```{figure} ../diagrams/linux_fs.svg
:width: 85%
:align: center

User space and kernel space are separated by a system-call gate; the kernel mediates all hardware access.
```

| Space | Runs | Privilege |
| --- | --- | --- |
| **Kernel (ring 0)** | kernel, drivers, scheduler, VFS, net | full hardware access |
| **User (ring 3)** | shells, apps, daemons | limited; asks kernel via syscalls |

**Communication**: system calls (`open`, `read`, `socket`); **procfs/sysfs** expose kernel state
as files. Recent distros boot with **systemd** (PID 1).

## The Shell Environment

The **shell** (`bash`, `sh`) runs commands. A robust script begins:

```bash
#!/bin/bash
set -euo pipefail        # exit on error, undefined vars error, pipe fails
VAR="value"
for i in 1 2 3; do echo "item $i"; done     # for/while/case, functions
# redirection: > (overwrite), >> (append), < (stdin), 2>&1 (stderr->stdout)
# pipe: cmd1 | cmd2  (stdout of left -> stdin of right)
```

| Item | Meaning |
| --- | --- |
| **Login shell** | reads `/etc/profile` then `~/.bash_profile` |
| **Interactive non-login** | reads `~/.bashrc` |
| **PATH** | ordered search dirs for commands (first match wins) |
| **Expansion** | globs (`*`), tilde (`~`), command substitution `$(...)` |

:::{tip}
Redirect stdout to a file **and** show it: `cmd | tee -a note.txt`.
:::

## File Systems Hierarchy

Linux uses a single root tree; physical/logical FS are mounted *at* points.

| Dir | Purpose |
| --- | --- |
| `/` | root |
| `/etc` | host config files |
| `/var/log` | logs |
| `/home` | user homes |
| `/tmp` | world-writable temp |
| `/opt` | third-party apps |
| `/dev`, `/proc`, `/sys` | devices + virtual kernel info |
| `/usr` | shareable user commands/libs |

| FS | Notes |
| --- | --- |
| **ext4** | journal, default |
| **XFS / Btrfs** | alternates |
| **tmpfs** | in-memory (/tmp, /dev/shm) |

Out of **inodes** (`df -i`) is a classic "disk full" cause even when space remains.

## Users, Groups, Permissions

| File | Role |
| --- | --- |
| `/etc/passwd` | users (UID, home, shell) |
| `/etc/shadow` | password hashes (must be unreadable) |
| `/etc/group` | groups |

```bash
useradd -m -s /bin/bash alice
usermod -aG docker alice     # add to supplementary group
passwd -l alice             # lock; passwd -u to unlock
```

**Permissions**: `r=4, w=2, x=1` summed as **octal** per triplet (user/group/other).

$$
\text{mode digit} = 4\cdot r + 2\cdot w + 1\cdot x
$$

| Command | Meaning |
| --- | --- |
| `chmod 755 f` | rwxr-xr-x |
| `chmod 600 f` | rw------- (owner only) |
| `chmod u+x,go-w f` | symbolic |
| `chown alice:devs f` | owner:group |

**Special bits**: setuid `u+s` (4755), setgid `g+s` (2755), sticky `+t` (1777).

## Process Management

A **process** is a running program; a **thread** is the CPU scheduling unit inside a process.

- **Scheduler**: CFS (normal) + real-time policies. `nice -20..19` adjusts priority.
- `ps aux`, `top`/`htop` to view; `kill PID` (SIGTERM) or `kill -9 PID` (SIGKILL);
  `kill -l` lists signals.
- `kill -STOP PID` pauses; `kill -CONT PID` resumes.

| Signal | Use |
| --- | --- |
| TERM (15) | graceful stop (catchable) |
| KILL (9) | force (uncatchable) |
| HUP (1) | often reload config |
| INT (2) | Ctrl-C |

## Services and systemd

Boot path: firmware → **GRUB** → kernel → **systemd** (PID 1) → *targets* (≡ runlevels).

| Target | Runlevel | Purpose |
| --- | --- | --- |
| multi-user.target | 3 | headless multi-user |
| graphical.target | 5 | GUI |
| rescue.target | 1 | single-user repair |

```bash
systemctl status nginx
systemctl enable --now nginx     # enable at boot + start
systemctl daemon-reload          # after editing a unit
journalctl -u nginx -f           # live logs for the unit
```

**Resources**: `ulimit` (per-process), **cgroups** (CPU/mem/I/O limits for groups).

## SSH and Remote Access

**SSH** encrypts login + file transfer (replaces telnet/rsh/ftp).

```bash
ssh alice@host.example.com
ssh -i key.pem ec2-user@IP          # Linux EC2
scp file.txt host:/tmp/
rsync -avz dir/ host:/opt/
```

`~/.ssh/config` simplifies:
```
Host bastion
    HostName 203.0.113.10
    User ec2-user
    IdentityFile ~/.ssh/bastion.pem
```

**Hardening**: `PasswordAuthentication no`, `PermitRootLogin no`, key pairs only, restrict by
Security Group source IPs, MFA for CLI (STS) where possible.

## Checkpoint

```{dropdown} Q1. Into which two rings is Linux split, and what gates the crossing?
**Answer.** Ring 0 (kernel) and ring 3 (user); crossing happens only via **system calls**.
```
```{dropdown} Q2. What does 'set -euo pipefail' do in a shell script?
**Answer.** `-e` exit on any error, `-u` error on undefined variable, `-o pipefail` make a
pipeline fail if *any* command fails (not just the last).
```
```{dropdown} Q3. If a file's mode is 750, what can the group do, and what is the 'sticky' bit?
**Answer.** Group=5 (`r-x`): read + execute; the **sticky bit** (`+t`, e.g., /tmp) means only a
file's *owner* can delete or rename its files.
```
```{dropdown} Q4. You see an nginx process hung. What single command gently asks it to quit?
**Answer.** `kill PID` (sends SIGTERM) — graceful. Use `kill -9 PID` only if it ignores SIGTERM.
```
```{dropdown} Q5. What does 'systemctl enable' do vs 'systemctl start'?
**Answer.** `start` launches now; `enable` makes it **auto-start at boot** (writes a symlink to
the unit's target wants directory).
```
